# XTrack-B launch on 2028

The user authorized training and selected 2028 with all three visible RTX 3090 GPUs.
2025 has four GPUs, but is not the selected training server.

This run trains one RGB-T/RGB-D/RGB-Event model with the author AdamW recipe,
the existing LasHeR, DepthTrack, and VisEvent train pools, and seed 2026.
Per-rank batch is 8, global batch is 24, and each epoch has 60,000 examples
and 2,500 optimizer steps. The 65-epoch low-disk configuration saves only
the final checkpoint. RGBT234 and VOT-RGBD evaluation remain deferred.
Future optimizer comparisons must use the same three-GPU configuration.

The author training entry uses `fail_safe=True`, which catches an exception
and can still print `Finished training!`. We set this existing option to
False so a failed training job exits with an error. No model, loss, or
parameter-freezing change is included.

The following commands are the exact environment and real-data validation
invocations. The smoke run is disposable: 48 train examples, 48 validation
examples, two optimizer updates per rank, and one separate epoch-1 checkpoint.
The report must contain `DDP_PREFLIGHT_PASS`, all three task names, matching
trainable parameter hashes across ranks, and finite losses and gradients.

```powershell
ssh -o BatchMode=yes -o ClearAllForwardings=yes -o ConnectTimeout=12 2028 'CUDA_VISIBLE_DEVICES=0,1,2 /data/gb/conda/envs/rgbx-risk/bin/python /data/gb/rgbx-risk/scripts/gpu_witness.py'
ssh -o BatchMode=yes -o ClearAllForwardings=yes -o ConnectTimeout=12 2028 'bash /data/gb/rgbx-risk/scripts/train_xtrack_3gpu.sh rgbx_b_adamw_3gpu_smoke /data/gb/rgbx-risk/outputs/ddp_smoke_20261002 > /data/gb/rgbx-risk/logs/ddp_smoke_20261002.log 2>&1; result=$?; tail -n 12 /data/gb/rgbx-risk/logs/ddp_smoke_20261002.log; exit $result'
```

After successful validation, the formal run uses a detached tmux session.
`run_xtrack_job.py` records the launcher PID, command, latest training metric,
GPU state, and exit code every 240 seconds. It does not restart training.
It verifies epoch 65 and finite model parameters and loss history before
marking the run completed. Run receipt and stdout are under `reports/` and
`logs/`; training logs and checkpoints are under the run's `outputs/` directory.
