# 共享参数范围（源码检查，尚未实现新优化器）

XTrack 作者的 `get_optimizer_scheduler` 将名称不含 `MeME` 的参数冻结。
因此，骨干原注意力、FFN 和定位头不能作为新方法“优化共享参数”的对象。
实际 trainable 清单与各任务梯度参与情况由 `reports/preflight_xtrack.json` 记录。

作者模型另有 `temporal_pos_embed_x/z` 两个新增参数，OSTrack 权重不含它们。
它们按作者代码随机初始化且在当前冻结策略下不更新；源码只在 384 分辨率时使用，
当前 B256 配置不使用。初始化核查保留这些作者行为，不把它们误判成预训练加载缺失。

在 MeME 内，源码明确共同使用的候选范围包括 `shared_expert`、`shared_expert1`、
`rgb`、`dte`、`dteall`、`fuse`、输出投影 `ffn1_1` 以及实际被使用的 MeME normalization。
`w_gate`/`w_noise` 是共同路由状态，是否与共享内容参数一起修正，应作为明确实验选择。
不能把这些候选名称规则当成已实现且已验证的参数掩码。

`experts.0` 至 `experts.5` 由路由选择，监督目标将前两维关联 T、中间两维关联 E、
最后两维关联 D。跨任务可访问同一专家，并不自动证明它在方法定义中是共享参数。
首版风险修正不应把所有专家统一纳入；专用专家仍使用自身正常更新。
全模型更新风险检查必须包含专用参数的变化。

新优化器实现前，需要按前向数据流确定最终掩码，并分别记录共享/专用/冻结范围，
不能仅凭一个实际批次有非零梯度就判定语义共享。
